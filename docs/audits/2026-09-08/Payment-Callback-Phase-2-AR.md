# الدفعة الثانية: تأكيد الدفع ومنع تكراره

التاريخ: 2026-09-09. الحالة: جاهزة محليًا للاختبار؛ لم تُنشر بواسطة المساعد. الدفعة الأولى فُحصت عبر Postman ونُشرت دون مشاكل بحسب إفادة صاحب المشروع.

## ما تغير

- مطابقة CustomerReference مع رقم المعاملة المحلي، وInvoiceId مع المعرّف المحفوظ. دعم السجلات القديمة التي احتفظت بـPaymentId بشرط وجوده في معاملات الفاتورة نفسها.
- مطابقة InvoiceValue والمبلغ المعروض بالريال السعودي مع المبلغ المحلي بدقة الهللة. تقبل صيغة SAR أو SR، وترفض البيانات الناقصة أو العملة المختلفة.
- الإبقاء على paymentId وId وInvoiceId والمعرف المحفوظ. صفحة الدفع الحالية قد ترسل InvoiceId داخل paymentId، وهذا السلوك مدعوم.
- قراءة نتيجة البوابة قبل قفل قاعدة البيانات؛ ثم إعادة قراءة المعاملة باستخدام lockForUpdate داخل DB transaction. العملية الناجحة سابقًا لا تُنفذ آثارها مرة ثانية ولا تتراجع إلى فشل أو إلغاء.
- قفل مستخدم العملية والطلب أثناء تسجيل الأثر المالي. حالة النجاح وحفظ الأثر المالي ضمن المعاملة نفسها؛ عند حدوث استثناء يتراجع الحفظ ويمكن إعادة المحاولة.
- استخدام المبلغ المحلي المطابق للبوابة في الدفع السريع وشحن المحفظة. إضافة مرجع المعاملة إلى قيد المحفظة. منطق مزايا باقات المحفظة الحالي لم يتغير.
- نجاح مؤكد متأخر يستطيع استكمال طلب كانت حالته failed_payment أو cancel_payment. لا يتم إلغاء طلب نشط عند وصول callback إلغاء قديم.
- الحالة Pending لا تلغي الطلب. تظهر رسالة عربية/إنجليزية تطلب مراجعة الحالة قبل الدفع مرة أخرى.
- أخطاء التحقق تعرض رسالة عامة بدل تفاصيل الاستثناء الداخلية.

المسارات وحقول API ورمز الدخول الثابت لم تتغير. لا توجد migrations جديدة.

استُخدمت [وثائق GetPaymentStatus الرسمية](https://docs.myfatoorah.com/docs/get-payment-status) لتحديد معنى حقول الفاتورة والمعرفات. التحقق المالي الحالي يفترض الحساب السعودي الذي يستخدمه التكامل القائم؛ حساب تجريبي بعملة أساسية مختلفة لا يمثل هذه التهيئة.

## التحقق المنفذ وحدوده

الأمر: php vendor/phpunit/phpunit/phpunit tests/Feature/Audit tests/Unit/Audit --no-progress

النتيجة: 23 اختبارًا و235 تحققًا ناجحًا؛ منها 13 اختبارًا جديدًا لمسار الدفع. اجتاز ملفا PHP الخاصان بالتنفيذ فحص الصياغة ونجح git diff --check. اختُبر أيضًا توليد HTML لرسالة الدفع المعلقة.

اختبارات الدفع تستخدم SQLite مؤقتة واستجابة بوابة مزيفة. خدمات التسجيل المالي تُستبدل بخدمات اختبار تكتب قيودًا وأرصدة داخل قاعدة الاختبار، للتحقق من عدد الاستدعاءات والتراجع الذري. لم تُختبر كامل مراقبات النماذج وخدمات المحفظة الفعلية أو الإشعارات التابعة لها. اختبار إعادة قراءة الحالة يحاكي تغيرها أثناء انتظار البوابة؛ لا يثبت تزامن الأقفال تحت حمل MySQL فعلي. لا دفعات أو رسائل حقيقية ولا تغييرات في بيانات السيرفر.

## فحص Postman والتطبيق قبل اعتماد الدفعة

استخدم بيئة دفع تجريبية سعودية وبيانات اختبار. يجب أن تكون الفاتورة منشأة من هذه البيئة وأن يطابق مرجعها المعاملة المحلية؛ لا يمكن إثبات نجاح الدفع بمجرد إرسال status=Paid في Postman.

مسار التأكيد الحالي:

GET {{base_url}}/ar/payment-gateway/{{transaction_id}}/callback?paymentId={{payment_id}}

عطّل متابعة التحويلات تلقائيًا في Postman لرؤية Location، وراجع القيد المالي وحالة الطلب أيضًا؛ رد التحويل وحده لا يكفي لإثبات الأثر المالي.

| التجربة | المتوقع |
| --- | --- |
| نجاح شحن محفظة، ثم إرسال callback نفسه مرتين | نجاح بلا قيد شحن إضافي |
| نجاح طلب عادي وطلب سريع | تسجيل المبلغ الصحيح مرة واحدة |
| paymentId لفاتورة تخص معاملة أخرى | رفض دون تغيير المعاملة أو الرصيد |
| callback مع InvoiceId أو المعرّف القديم | استمرار التوافق إذا كانت الفاتورة مطابقة |
| فاتورة Pending | لا إلغاء للطلب، ورسالة انتظار واضحة |
| نجاح ثم callback قديم فاشل/ملغى | بقاء النجاح دون تكرار الأثر |
| فشل حفظ داخل بيئة الاختبار ثم إعادة المحاولة | عدم بقاء قيد جزئي، ونجاح المحاولة اللاحقة مرة واحدة |
| callback متزامنان على MySQL/InnoDB | قيد مالي واحد؛ هذا الفحص مطلوب ولم يُنفذ هنا |

## حدود هذه الدفعة والباقي

بند A04 ما زال جزئيًا: هذا الإصلاح يخص callback الخاص بصفحة الدفع. يلزم استكمال مراجعة مسارات الدفع القديمة التي تحدث الحالة أو تشحن مباشرة من API، والتحقق من تسعير باقات المحفظة، ومنع إنشاء أكثر من محاولة دفع متزامنة للمعاملة نفسها، وضمان تفرد المراجع المحلية. لا يُفترض أن قفل callback وحده يعالج هذه المسارات أو يمنع خصم البوابة مرتين عند إنشاء فواتير متعددة. كما يلزم فحص إرسال الإشعارات بعد commit واختبارات خدمات المال الفعلية. بقية تحسينات الأداء والسيو والتشغيل في التقرير ما زالت مفتوحة.
