# المرحلة الحادية عشرة: تحسين PageSpeed للصفحة الرئيسية

التاريخ: 2026-09-11. الحالة: منفذة محليًا ومختبرة؛ يلزم إعادة قياس PageSpeed بعد النشر.

## الدليل

أظهر التقرير المرفق أداء سطح المكتب 87 وأداء الهاتف 37، مع FCP للهاتف نحو 4.2 ثوانٍ وLCP نحو 10.4 ثوانٍ وTBT نحو 1.4 ثانية. كانت Accessibility نحو 82 وBest Practices نحو 50 في الهاتف، بينما SEO 100. لذلك ركزت الدفعة على موارد العرض الأولى وJavaScript الخارجي وإمكانية الوصول، ولم أغيّر API أو الدفع أو المحفظة.

## التغييرات

- CSS الخاص بـAOS وSwiper أصبح preload غير حاجب للرسم، مع noscript fallback.
- سكربتات AOS وSwiper وSweetAlert أصبحت `defer`. تهيئة AOS تنتظر DOMContentLoaded بعد توفر المكتبة، مع fallback المحتوى الموجود سابقًا.
- تحميل أدوات التتبع الخارجية لا يحدث تلقائيًا خلال أول 4 ثوانٍ؛ أصبح بعد 12 ثانية كحد أقصى أو فور scroll/touchstart كما كان عند التفاعل. أكواد التتبع والأحداث نفسها لم تتغير.
- أزيل `maximum-scale=1.0,user-scalable=no` من viewport حتى يستطيع مستخدم الهاتف التكبير.
- أضيفت preconnect للخطوط وCDN، واسم وصول لزر واتساب العائم مع `rel=noopener`.

## التحقق

- PHPUnit: `OK (69 tests, 499 assertions)`.
- Vite build: ناجح، 55 module.
- PHP lint و`git diff --check`: ناجحان.
- لم يُعد تشغيل PageSpeed بعد هذه الدفعة من داخل البيئة؛ الأرقام الجديدة يجب أخذها من PageSpeed على الرابط المنشور وفي نافذة خفية، مع اختبار الهاتف وسطح المكتب.

## ضغط الصور المنفذ

تم تنزيل الأصول المنشورة للتحليل فقط: صورة شاشة البداية كانت 818,586 بايتًا وأصبحت نسخة WebP بحجم 71,228 بايتًا، وصورة قسم التطبيق كانت 1,229,299 بايتًا وأصبحت 57,782 بايتًا. أضيفت النسخ إلى `public/assets/images/optimized/`. يستخدم القالب النسخة المضغوطة فقط عند تطابق اسم الملف الحالي، مع fallback للصورة الديناميكية؛ لذلك لا يتغير محتوى الإدارة إذا استُبدلت الصورة لاحقًا. أبعاد صورة البداية في HTML أصبحت 277×600 لتطابق نسبة المصدر.

## القيود والإجراء التالي

صور Unsplash وبادجات المتاجر ما زالت خارجية وتحتاج قياسًا أو استضافة محلية إذا بقيت ضمن أكبر الموارد. يجب ضغطها إلى WebP/AVIF وتقديم نسخة بعرض مناسب من لوحة التخزين أو CDN، ثم إعادة القياس. كما أن خفض TBT إضافيًا يحتاج تقرير Lighthouse التفصيلي بعد النشر لتحديد أطول third-party task قبل حذف أي تكامل تسويقي.
